# Results

The paper Table 1 is generated by `scripts/build_paper_table.py` from
`main_tables/dtob6_0826_per_seed_raw.csv` and
`profiling/dtob6_0826_gc_controlled.json`. The output CSV retains full precision;
LaTeX rounds once to two decimal places. The image is a reference for the paper
version and is not used as a numerical input.

Accuracy and 99-query inference latency are recomputed as mean plus sample
standard deviation over seeds 7, 17 and 27. Parameter counts are checked
against the profiling identities. Memory is allocated training-profile memory.
The selected profiling cohort uses 20 warm-up and 50 measured steps, with
Python cyclic GC excluded. Transolver is 193.12437805175782 ms, displayed as
193.12 ms. The earlier 20260828 profile is a different timing run and is not
silently substituted.

Five external baselines have machine-readable exported profiling summaries
with original profile SHA-256 values; their original per-step profile JSONs
have not been recovered. Both LTS variants include all 50 original measured
latencies, whose mean and sample standard deviation are validated. Source
export hashes, identities and evidence types are in the profiling JSON.
`main_tables/paper_table_provenance.json` records input and output hashes.

Direct rounding from full-precision sources differs from the supplied image
in four cells: GeoTS-FLARE stress 1.80%, Transolver-3 inference 4463.00 ms,
Base inference s.d. 4.22 ms, and Full training latency 29.75 ms. Intermediate
rounding is not used to force the values to match the image.

Base disables CA, Fourier and D-Scale; Full enables all three. Only CA uses
component labels. D-Scale is named `trajectory_envelope` / `tenv` internally.

Historical `main_tables/dtob6_0826_raw.csv` and `*_per_seed_raw.csv` retain
their original ratio-unit metrics and measurement boundaries. The ablation
aggregate memory column is not the profiled memory in Table 1.

Formal routing tables and configs release K = {1, 2, 3, 4, 6, 12}; the
separate legacy eight-layer study releases K = {1, 2, 4}. Import and current
repository hashes are recorded in `ablations/droptest/source_provenance.json`.
The two scales are not interchangeable. See
[`droptest_ablations.md`](../protocols/droptest_ablations.md).
